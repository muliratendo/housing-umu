# URLM Request Inventory

## Inventory method and route count

`php artisan route:list --except-vendor --json` reported **129 registered
routes**. The table below contains one row for every route, including routes
with no discovered browser caller. `GET|HEAD` means Laravel accepts both
methods. `none discovered` is intentional and means repository searches found
no frontend caller.

Common middleware is expanded in the `Middleware / authorization` column:

- `web` means the session-aware web stack.
- `student` means `auth`, `verified`, and `role:student|student_leader`.
- `admin` means `auth`, `verified`, the admin role/permission gate, plus the
  route-specific permission shown after `;`.
- `guest-auth` means `redirect.authenticated`.
- `auth` means the authenticated web stack.
- `api-log` means the API route plus `throttle:client-logs`.
- `sanctum` means `auth:sanctum`.

The profile shorthand in the `Policy` column is:

`kind/scope/criticality/concurrency/retry/timeout/idempotency/reconcile`.

### Caller and route gaps

- No frontend caller was found for routes 9, 52–55, 60–64, 67–72, 76, and
  several admin actions may be reached through components not found by the
  static request search. They remain inventoried as server/admin operations.
- Route 9 is registered as `/admin/admin/academic-terms/{term}/deactivate`;
  the malformed URI text appears to be an existing route-definition defect,
  not a URLM change.
- The student application route source contains two identical
  `GET /student/applications/{application}/edit` definitions with the same
  route name. This is a duplicate method-and-URI combination in the source;
  Laravel's route listing reports one registered row for it. It is not a
  duplicate between inventory rows 105 and 111: row 105 is the distinct,
  malformed submit URI `/student/applications/applications/{application}/submit`,
  while row 111 is the edit URI.
- Static-versus-parameter ordering is a concern in the student application
  group because `/create` is declared before `/{application}`, while the
  duplicate edit definition should be removed only in a separately authorized
  route-defect pass.
- No additional duplicate method-and-URI combinations were identified in the
  129-route registration output.
- Several controllers validate inline rather than through dedicated Form
  Requests; the table records `controller` rather than implying a missing
  server validation boundary.
